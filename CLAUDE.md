# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Agent Room": an Express + TypeScript app (run directly with `tsx`, no build step) that runs a sprint SDLC pipeline of role agents (System Analyst → Software Lead → QA Design → Architecture → Coding → QA Unit → Deploy → QA E2E → DevOps). A person approves between stages and before any write to Jira, Confluence, Figma, GitHub or Jenkins. The frontend is plain HTML/JS/CSS in `public/` with no framework or bundler.

## Commands

- `npm run dev`: starts the server with watch (`tsx watch src/server.ts`) on `PORT` (default 4173).
- `npm start`: starts the server without watch.
- `npm run check`: runs `src/walkthrough.ts`. This is the only test. It is an assertion script, not a test framework. It drives the full pipeline with the offline draft runner and checks credential sealing, which sources each role gets, approval gating and prior-output handoff. Add new checks to this file.
- Type check: `npx tsc --noEmit`. No script or linter is configured.

Config is read from `.env` by the custom loader in `src/env.ts` (not dotenv). See `.env.example`. Without `CURSOR_API_KEY`, the app runs in **draft mode**: each role returns the `## Draft` section of its agent file instead of calling an LLM.

Git may fail with "dubious ownership" on `D:/Agents`. That is a Windows ACL problem. Ask the user before running `git config --global --add safe.directory`.

## Architecture

**Agents are markdown files.** `agents/NN-*.md` hold the prebuilt roles. Each has front matter (`name`, `title`, `needs_approval`), the role instructions, and a required `## Draft` section that serves as the offline output. `{{requirement}}`, `{{confluence_title}}` and `{{confluence_note}}` are substituted in `runLocal`. Roles run in filename order. Users can also create custom agents (`data/custom-agents/<workspaceId>/`) and teams (`data/teams.json`) through `src/catalog.ts` and `src/teams.ts`. A room's `teamId` decides which agents run (`roomAgents` in server.ts). With no `teamId`, it uses the default "SDLC Sprint Team".

**Pipeline (`src/router.ts`).** A `Room` (`src/types.ts`) holds `stages[]`, `messages[]`, `permissions[]` and the Setup sources. `runUntilWait` runs `pending` stages in order. When a stage has `needs_approval`, it stops at `waiting_approval`. `approveAndContinue` and `retry` resume the run. Each stage gets a `Packet` built from: the requirement, `project/AGENTS.md`, the outputs of finished prior stages (outputs only, never tool logs), the person's notes, shared memory, and the sources returned by `hooks.loadSources`. Router functions are pure-ish. They clone the room and report progress through `RunHooks`, so the walkthrough can drive them without the server.

**Source scoping.** `loadSourcesForRole` in `src/server.ts` decides which external sources each role sees. Confluence/pasted BRD and Figma go only to `sa` and `software-lead`. Git repos go to a defined set of roles. The walkthrough asserts this scoping, for example that QA Design gets no Confluence source.

**Runners (`src/runner.ts`).** `selectRunner` returns either the draft runner or the Cursor SDK runner (`@cursor/sdk`, `CURSOR_RUNTIME=local|cloud`). `buildPrompt` builds the full prompt. The last prompt sent is written to `data/workdir/last-prompt.md`.

**Write-backs are parsed from agent output.** `parseWritePlans` in `src/permissions.ts` reads markdown tables under a `## Write plan` heading (columns: System | Action | Target | Payload summary) and turns each row into a `PermissionRequest`. The UI shows these as permission cards. `POST /api/room/permissions/:id/approve` runs them through `executePermission` in server.ts, which dispatches to `jira.ts`, `atlassian.ts`, `figma.ts`, `github.ts` (multi-repo PRs via `workdir.ts`) or `jenkins.ts`. If you change the Write plan format in an agent file, update the parser too.

**Runtime permissions (Cursor CLI-style).** With `CURSOR_RUNTIME=local`, agents get write tools (`src/tools.ts`) as SDK `customTools`. Cursor's own shell, edit and delete tools are turned off. A tool call adds a `mode: "runtime"` permission to the live room and blocks on `PermissionGate.ask` (`src/gate.ts`). The UI polls `GET /api/permissions/live` while a run is open and answers through the same `/api/room/permissions/:id/approve|deny` routes, which check the gate before the card flow. The tool then runs `executePermission` and returns `OK:`, `DENIED:` or `FAILED:` text to the model. Asks are denied automatically after `PERMISSION_TIMEOUT_MS` (default 15 minutes). Write plan cards remain the fallback for draft and cloud modes. Write tool results say who approved them ("OK (approved by the person at …)"), because the model cannot see the Allow click. `jira_update_issue` changes summary/description only. `jira_move_to_sprint` (a write tool) and `jira_list_sprints` (a read tool) use the Jira Software Agile API on the Setup board (`boardIdFor` parses `…/boards/<id>`), and `findSprint` refuses ambiguous names. Optional Atlassian scopes (comment reading, sprints) are requested only when they are listed in `ATLASSIAN_EXTRA_SCOPES`, because Atlassian refuses consent for scopes the app has not enabled. **Read tools** (`READ_TOOLS` in `src/tools.ts`: `confluence_read_comments`, which needs the `read:comment:confluence` scope, plus `figma_list_frames`, `figma_read_frame`, `figma_frame_image`) run without asking, through `readTool` in server.ts. `figma_frame_image` returns a PNG as an image content block. All Figma API calls go through `figmaAccess`, which uses `FIGMA_ACCESS_TOKEN` (a personal access token, sent in the `X-Figma-Token` header) when it is set, and otherwise the person's OAuth login.

**Group chat (`src/group.ts`).** SA, Software Lead and QA Design discuss the requirement in one thread (`data/groups/<roomId>.json`), one speaker at a time. Each member keeps its own Cursor agent: the first turn sends the full context, and later turns use `Agent.resume` with only the unseen messages. Every reply must end with `[[NEXT: name]]`, `[[ASK]]` or `[[DONE]]`. `pickNextSpeaker` picks in this order: the person's @mention, then a member who has waited at least 2×members agent turns (so two agents can't ping-pong and starve the third), then the floor handed over with `[[NEXT]]`, then an @mention in the last message, then the member not done who spoke least recently. Every follow-up starts with `identityReminder` (who you are; never write as a teammate) and `personRecap` (everything the person said, treated as decisions). Long resumed sessions get compacted, and without these, small models drift into a teammate's role and forget earlier answers. A run stops when everyone is done, on `[[ASK]]`, on Pause, or at `GROUP_MAX_TURNS` (default 12). `POST /api/group/message` starts a streamed run; if a run is already going, the message joins the live thread instead. Group members see all sources (`loadSourcesForRole(..., shared = true)`). **Kickoff replaces the first pipeline roles:** `POST /api/group/handoff` runs `handoffStages`, which marks the members' stages done and uses their group messages as the outputs. It then streams `runUntilWait`, which continues at Architecture.

**Frontend (`public/`).** A chat app with a sidebar, no framework. `showView()` switches between `wizard`, `kickoff`, `build`, `dm` and `settings`. Elements shared between views are moved into the active view with JS:
- the setup blocks in `#parts` go into the wizard or the Settings → Sprint sources tab;
- `#live-asks` goes into the open chat's `.ask-slot`.

Keep element IDs stable, because handlers look them up once at load. Agent text is rendered by the small built-in `renderMarkdown`, which escapes the text first. The Build view hides the kickoff members' stages and messages.

**Code access (`src/code.ts`).** `CODE_WORKSPACE` points at local clones: a `.code-workspace` file or a folder of clones, matched to Setup repos by their `origin` URL. For each Setup repo, `snapshotRepo` runs `git fetch` (at most every 5 minutes, never prompting), resolves the Setup branch loosely (`UI-Sprint_06` matches `origin/UI-Sprint-06`), and exports it with `git archive` into `data/workdir/code/<owner>__<repo>`. It re-extracts only when the commit changes, and the person's working copy is never touched. `codeSources` in server.ts adds each snapshot as a `SourceDoc` with `localPath`. `codeDirs` then passes those folders to the Cursor agent as `local.dirs`, so it can read them with Cursor's read/grep/glob/ls tools (shell and edit stay disabled).

**Design exports.** `DESIGNS_DIR` is a folder of screens exported from Figma by hand. `designsSource` lists the images, with modified times so that re-exports reach resumed agents, and passes the folder as `localPath`. Cursor's read tool shows an image to the model (verified), so no Figma API calls are needed. **`design_annotate`** (a read tool, no approval) draws numbered red boxes, positioned in percent of the image, on a copy of an exported PNG (`src/annotate.ts`, pure-JS `pngjs`). It saves the copy to `data/workdir/annotations`, served at `/api/annotations/<file>`, and returns a downscaled preview so the model can check and correct its boxes. `renderMarkdown` only displays images from that path. `jira_attach_image` (a write tool) uploads an annotated file as a Jira attachment, with an optional comment.

**Shared memory and DMs.** `src/memory.ts` indexes agent outputs and permission results (gaps, decisions, tests, approvals, PRs) into `data/memory/<roomId>.json`. That memory goes back into every later packet. `src/dm.ts` stores one-to-one chat threads with each agent (`data/dms/<roomId>/<agent>.json`). DM replies can also produce Write plans, marked `surface: "dm"`.

**Persistence.** All state is JSON under `data/` (gitignored; overridable with `DATA_DIR` for the room file): `room.json` (one current room), `auth.json` (users and workspaces), `secrets.json` (generated session secret and credentials key), and `credentials/*.enc` (OAuth tokens encrypted with AES via `src/crypto.ts`). `normalizeRoom`/`recover`/`clone` default every optional `Room` field. **When you add a field to `Room`, add its default in all of `store.ts` `normalizeRoom`, `router.ts` `openRoom`, `softResetRoom`, `recover` and `clone`.** On startup, a stage still marked `running` is set to `error`.

**Server (`src/server.ts`).** A single large file holds all routes: auth/session (sealed cookie), catalog/teams, OAuth flows for Atlassian, Figma and GitHub (`/auth/<provider>` and `/callback`), room Setup sources (`/api/room/*-source`), memory, DMs, Jenkins smoke callback (`/api/jenkins/smoke`, token-protected), and health. Pipeline routes (`/api/room/start|approve|retry`) stream NDJSON events (`room`, `delta`, `error`) through `streamRun`. A global `busy` flag allows one run at a time. `smoke.ts`, `e2e.ts` (optional Playwright), `assertions.ts` (extracts TEST-/UNIT- specs from QA output) and `devops.ts` support the Deploy, QA and DevOps phases.

## Project docs and rules

- `project/AGENTS.md` is the project profile included in every agent prompt. It holds the rules every role follows: cite sources, record gaps instead of inventing requirements, never write externally without an approved Write plan, stay inside the role, and respect the Dev → Testing → Preprod → Prod ladder and the Jira Epic → Story → Subtask → Bug hierarchy.
- `project/BUILD-ROADMAP.md` is the phase-by-phase checklist (Phases 0–8) and the source of truth for what is done and what comes next. `project/SDLC-DESIGN.md` describes the target design.
- Prompts and packets must never contain tokens or credentials. The walkthrough checks this.
